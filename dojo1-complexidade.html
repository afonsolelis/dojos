Round 1

Encontrando Duplicados

O Problema

Dada uma lista de números inteiros, descubra se há algum número duplicado. Retorne true se houver duplicidade ou false caso não haja.


// Exemplos:
temDuplicado([1, 2, 3, 1]) // Retorna: true
temDuplicado([1, 2, 3, 4]) // Retorna: false

Fase 1: A Força Bruta

Plateia: Qual a primeira ideia que vem à mente para garantir que encontramos um par duplicado?

Dica: Compare todos os elementos uns com os outros.

💻 DRIVER 1: Vá para o teclado! Implemente a solução de Força Bruta.

Intervenção / Análise

Professor: Olhem para os loops. Qual a complexidade dessa solução inicial?

  • Quantas iterações temos para N elementos?
  • Complexidade de Tempo: O(n²) 🐢
  • Qual a Complexidade de Espaço? (Criamos variáveis extras baseadas em N?)
  • Complexidade de Espaço: O(1) 🚀

Fase 2: Otimização (Trade-off)

Professor: "Isso vai estourar o limite de tempo (Time Limit Exceeded) em grandes volumes."

Como resolver em Tempo O(n)?

Plateia: Podemos gastar memória ("sacrificar Espaço") para ganhar processamento!

⏱️ DRIVER 2: Vá pro teclado! Altere a solução focado em O(n) iterando apenas 1 vez (Use Hash Set ou Mapa).

Análise da Otimização

  • O array é iterado paralelamente (uma única vez): Tempo O(n).
  • A busca em um Set (conjunto) é imediata: O(1) médio.
  • Mas armazenamos os elementos vistos: Espaço O(n).

Evolução: O(n²) ➡️ O(n)

Round 2

Two Sum (Alvo da Soma)

Problema clássico utilizado na triagem técnica de Big Techs (Amazon, Uber).

O Problema

Dado um array de inteiros e um valor alvo (target), retorne os elementos (ou índices) dos dois números que somados dão o alvo.


// Exemplos:
twoSum([2, 7, 11, 15], 9) 
// Retorna [2, 7], pois 2+7=9

twoSum([3, 2, 4], 6) 
// Retorna [2, 4], pois 2+4=6

Fase 1: Solução Inicial

Plateia: Guiar o driver com a estratégia mais segura (ainda que mais lenta).

Sim, estamos falando de dois loops aninhados novamente.

🔁 DRIVER 3: Implemente a primeira versão combinatória!

Análise Fria

Professor: Numa entrevista real da Uber, a solução de O(n²) é esperada nos primeiros 10 minutos, e então vem a pergunta:

"Excelente. Mas e se o array tiver 1 milhão de usuários? Você tem como fazer isso em O(n)?"

Fase 2: A Sacada Algorítmica

Ao invés de perguntar "quem na frente soma com meu número atual?", faça a pergunta reversa:

Qual o COMPLEMENTO que me falta para chegar no Target?


complemento = target - numeroAtual;
Verificamos se o "complemento" já passou no Histórico (Map/Obj).
⚡ DRIVER 4: Troca de guarda! Implemente refatorando pra O(n) utilizando memória auxiliar.

Round 3

Anagramas Válidos

O Problema

Dadas duas strings (palavras/frases), crie uma função que retorne true caso uma seja anagrama da outra (mesmas letras em ordem diferente).


// Exemplos:
isAnagram("padre", "pedra") // true
isAnagram("banco", "cabos") // false

Fase 1: Usando funções da linguagem

Plateia: Dá pra fazer numa linha só?

Quebre as strings, ordene (sort), depois una (join) e verifique igualdade!

🧹 DRIVER 5: Deixe a linguagem trabalhar por nós! (Implementem com Sort).

Análise do Sort()

Professor: O código está muito limpo! Mas qual a complexidade algorítmica oculta na função .sort()?

Maioria das linguagens usa QuickSort, MergeSort ou TimSort: O(n log n).

Isso é ótimo, mas O(n) ganha de O(n log n). Como fazemos em O(n)?

Fase 2: Contagem de Frequência

Plateia: Não podemos ordenar. Temos que contar as ocorrências de caracteres.

Dica: Podemos usar Mapa de Frequência, ou até um simples Array de 26 posições (alfabeto) para somar e subtrair ocorrências.

🛠️ DRIVER 6: Hora de finalizar com maestria e processamento O(n)!

Resumo da Aula

Big O Cheat Sheet

Notação Nome Exemplo Clássico
O(1) Constante Acesso de índice de Array, Busca em HashMap
O(log n) Logarítmica Busca Binária (Binary Search)
O(n) Linear Um único loop percorrendo um Array
O(n log n) Log Linear Algoritmos de Ordenação eficientes (MergeSort)
O(n²) Quadrática Loops aninhados (for dentro de for)
